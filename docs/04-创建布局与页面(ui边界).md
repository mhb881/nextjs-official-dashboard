# Chapter 4 — Creating Layouts and Pages

## 1. 本章学习目标

在上一章中，你学习了如何使用字体与图片优化技术。本章我们将通过嵌套布局（Nested Layouts）和页面（Pages）来构建仪表盘路由系统。

**本章涉及的核心主题：**

- 使用文件系统路由（File-system Routing）创建仪表盘路由。
- 理解文件夹与特殊文件在定义新路由段（Route Segments）时的作用。
- 创建一个可在多个仪表盘页面间共享的嵌套布局。
- 掌握文件同置（Colocation）、部分渲染（Partial Rendering）与根布局（Root Layout）的概念。

学完本章后，你应该能够：

1. 根据 `app/` 下的文件结构推导页面对应的 URL。
2. 解释 `page.tsx` 为什么是创建路由页面的特殊文件。
3. 理解 Colocation（代码共置）如何帮助组织页面相关代码。
4. 解释 `layout.tsx`、`children` 和共享 UI 之间的关系。
5. 区分 Root Layout 和 Nested Layout 的职责。
6. 理解 Partial Rendering 与布局复用、客户端 React State 保留之间的联系。

本章的核心不是记住几个特殊文件名，而是理解一个整体模型：

**文件系统负责组织路由，`page.tsx` 定义页面内容，`layout.tsx` 组织共享 UI，而嵌套布局将这些部分组合成最终页面。**

## 2. 嵌套路由（Nested Routing）：路由、页面与布局

Next.js 采用**基于文件系统的路由机制（File-system Routing）**，即通过文件夹层级来定义嵌套路由。每个文件夹代表一个映射到 URL 路径的**路由段（Route Segment）**。

![image-20261030073144003](./04-创建布局与页面(ui边界).assets/image-20261030073144003.png)

以本章的 Dashboard 应用为例：

```text
/app
 ├── layout.tsx
 ├── page.tsx            ---> /
 └── dashboard
      ├── layout.tsx
      ├── page.tsx       ---> /dashboard
      ├── customers
      │    └── page.tsx  ---> /dashboard/customers
      └── invoices
           └── page.tsx  ---> /dashboard/invoices
```

这个结构包含三种不同的职责：

| 文件或目录 | 职责 |
|---|---|
| `dashboard/`、`customers/`、`invoices/` | 组织嵌套路由的路径层级 |
| `page.tsx` | 定义相应路由的页面内容 |
| `layout.tsx` | 定义在特定路由范围内**共享的布局 UI** |

你可以使用 `layout.tsx` 和 `page.tsx` 等特殊文件为各个路由构建独立的 UI：

- `page.tsx` 是 Next.js 的专属特殊文件，用于导出一个 React 组件。**该文件是使路由能够被公开访问的必要条件**。在当前项目中，`/app/page.tsx` 已经存在，它对应根路径 `/` 的主页。
- 要创建嵌套路由，只需将文件夹层层嵌套，并在对应文件夹中放置 `page.tsx` 文件。例如，`/app/dashboard/page.tsx` 会映射到 `/dashboard` 路径。

![image-20261030073218803](./04-创建布局与页面(ui边界).assets/image-20261030073218803.png)

**需要注意**：不是 `app/` 下的每个普通文件或文件夹都会成为一个可访问的 URL。文件系统路由需要结合 Next.js 规定的特殊文件来识别路由页面。

**理解关键**：**目录**组织路径层级，**页面文件**提供路由对应的页面，**布局文件**组织多个页面之间共享的 UI。

## 3. 文件系统如何映射成 URL（File-system Routing）

### 3.1 文件夹与 Route Segment

Route Segment 可以**理解为路由路径中的一个片段**。

```text
/dashboard/customers
```

对应的目录结构是：

```text
app/
└── dashboard/
    └── customers/
        └── page.tsx
```

这里：

- `dashboard/` 对应路径片段 `dashboard`。
- `customers/` 对应路径片段 `customers`。
- `page.tsx` 定义该路由对应的页面内容。

因此，`app/dashboard/customers/page.tsx` 对应的路径是 `/dashboard/customers`。

---

### 3.2 通过实践验证路由映射（创建页面）

创建 Dashboard 下的三个页面：

```tsx
// app/dashboard/page.tsx
export default function Page() {
  return <p>Dashboard Page</p>;
}
```

```tsx
// app/dashboard/customers/page.tsx
export default function Page() {
  return <p>Customers Page</p>;
}
```

```tsx
// app/dashboard/invoices/page.tsx
export default function Page() {
  return <p>Invoices Page</p>;
}
```

开发服务器运行后，可以分别访问：

| URL | 页面内容 |
|---|---|
| `/dashboard` | Dashboard Page |
| `/dashboard/customers` | Customers Page |
| `/dashboard/invoices` | Invoices Page |

这就是在 Next.js 中创建不同页面的方式：**使用文件夹创建新的路由段，并在其中添加一个页面文件。**

这里的重点不是三个组件分别返回什么文本，而是它们如何通过不同的文件位置对应不同的 URL。

文件系统路由解决的是：**应用中的某个页面应该由什么路径访问？**理解了路径映射，才能进一步理解为什么一个路由可以有自己的页面内容，同时又能与其他页面共享布局。

## 4. Colocation：路由文件和相关代码如何共存

通过为页面文件规定专属命名，Next.js 允许你将 UI 组件、测试文件以及其他相关业务代码与路由文件同置（Colocate）在同一目录下。

什么是 [Colocation](https://nextjs.org/docs/app/getting-started/project-structure#colocation)？Colocation，**即代码共置，是指把相互关联的代码放在彼此接近的位置**。

**只有 `page` 文件内部导出的内容才会被公开访问**。例如，`/ui` 和 `/lib` 文件夹可以与路由一同放在 `/app` 目录下，而不会被意外暴露为公开页面。

```text
app/
├── dashboard/
│   ├── page.tsx
│   └── customers/
│       └── page.tsx
├── ui/
│   └── dashboard/
│       └── sidenav.tsx
└── lib/
```

> 这里的 `page.tsx` 有路由系统规定的特殊语义；`sidenav.tsx` 则是一个普通的 UI 组件文件。

这种组织方式可以让开发者更容易找到相关代码，而不必把所有内容都放到与路由完全分离的目录中。

需要区分两个概念：

- **代码共置解决组织问题**：相关代码放在哪里更容易维护。
- **特殊文件解决路由定义问题**：哪些文件按照 Next.js 约定参与路由构建。

## 5. 如何让多个页面共享 UI（Next.js 的 Layout）

这是本章的核心部分。

### 5.1 问题：多个 Dashboard 页面具有相同的界面结构

假设 Dashboard 有三个页面：

- `/dashboard`
- `/dashboard/customers`
- `/dashboard/invoices`

这三个页面可能具有相同的侧边栏，但主体内容不同。如果每个页面都独立实现 SideNav，就需要重复编写相同的界面结构。

更重要的是，侧边栏属于多个页面共同拥有的 UI，而不是某一个页面独有的内容。

在 Next.js 中，你可以使用特殊的 `layout.tsx` 文件来创建在多个页面之间共享的持久化 UI。

---

### 5.2 创建 Dashboard Layout ⭐⭐

在 `app/dashboard/` 下创建 `layout.tsx`：

```tsx
import SideNav from "~/ui/dashboard/sidenav";

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <div className="flex h-screen flex-col md:flex-row md:overflow-hidden">
      <div className="w-full flex-none md:w-64">
        <SideNav />
      </div>
      <div className="flex-grow p-6 md:overflow-y-auto md:p-10">{children}</div>
    </div>
  );
}
```

这段代码的核心机制如下：

1. 首先，你将 `<SideNav/>` 组件导入到了布局中。导入到该文件内的任何组件都会成为共享布局的一部分。
2. `<Layout/>` 组件接收一个 `children` prop。该子节点可以是一个页面（Page），也可以是更深层的另一个嵌套布局（Layout）。在当前场景下，`/dashboard` 目录下的所有页面都会自动嵌套在该 `<Layout/>` 之中。

![image-20261030081853122](./04-创建布局与页面(ui边界).assets/image-20261030081853122.png)

保存更改并在浏览器中查看本地服务，确认侧边导航与内容区域是否显示正常。

在 Next.js 中使用布局的一大优势是**部分渲染（[Partial Rendering](https://nextjs.org/docs/app/building-your-application/routing/linking-and-navigating#4-partial-rendering)）**：在页面间跳转时，**只有发生变化的内容页面会更新，而布局本身不会重新渲染**。这能够在页面切换过程中完整保留布局内客户端组件的 React 状态（如侧边栏滚动位置或输入状态）。

![image-20261030082137129](./04-创建布局与页面(ui边界).assets/image-20261030082137129.png)

---

### 5.3 `children` 到底是什么？

在 React 中，`children` 是一个常见的组件属性，用于接收嵌套在组件内部的内容。

```tsx
function Layout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div>
      <header>Dashboard</header>
      <main>{children}</main>
    </div>
  );
}
```

当某些内容被放进 `Layout` 组件内部时，这些内容可以通过 `children` 在指定的位置渲染。

在 Next.js App Router 中，**框架会按照路由匹配和布局规则，把相应的页面内容组合进布局**。因此，本章的 Dashboard Layout 不需要手动导入 Customers 和 Invoices 页面。**`children` 由框架根据当前路由提供**。

---

### 5.4 页面是怎样嵌入 Layout 的？

假设当前访问：

```text
/dashboard/customers
```

对应的页面组件为：

```tsx
// app/dashboard/customers/page.tsx
export default function Page() {
  return <p>Customers Page</p>;
}
```

在本章讨论的布局结构中，页面内容会出现在 Dashboard Layout 的 `{children}` 所在位置。

可以把它理解为：

```text
Dashboard Layout
├── SideNav
└── 页面主体
    └── Customers Page
```

如果访问 `/dashboard/invoices`，布局仍然是相应的 Dashboard Layout，只是当前页面内容变成 Invoices Page。

```text
Dashboard Layout
├── SideNav
└── 页面主体
    └── Invoices Page
```

两个结构的共同点是布局；区别是当前路由对应的页面内容。

---

### 5.5 从组件组合角度理解 Layout⭐⭐

这背后的设计思想是：**把稳定、可共享的 UI 结构与随路由变化的页面内容分开。**

从职责上看：

| 部分 | 负责什么 |
|---|---|
| `SideNav` | 提供 Dashboard 的共享侧边栏 |
| `Layout` | 组织侧边栏和页面主体的位置关系 |
| `children` | 提供当前匹配的子页面内容 |
| `page.tsx` | 定义当前路由对应的页面 |

需要注意，`children` 并不是一个专门负责路由匹配的 API。它是 React 组件的子内容属性；Next.js 的路由系统决定当前页面与布局如何组合。

> **Layout 的核心价值不是简单地少写几行代码，而是明确了共享结构与页面内容之间的职责边界**。

## 6. 根布局与嵌套布局：布局如何形成层级

### 6.1 Root Layout：整个应用的根布局

在第 3 章中，你已将 `Inter` 字体引入到了另一个布局文件 `/app/layout.tsx` 中：

```tsx
// app/layout.tsx
import type { Metadata } from "next";
import "./globals.css";
import { inter } from "~/ui/fonts";

export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};

export default function RootLayout({ children }: LayoutProps<"/">) {
  return (
    <html lang="en" className={`${inter.className} h-full antialiased`}>
      <body className="flex min-h-full flex-col">{children}</body>
    </html>
  );
}
```

该文件被称为**根布局（Root Layout）**，是每一个 Next.js 应用程序中**必不可少**的入口文件。

- 添加到根布局中的任何 UI 都会在应用的所有页面间共享。
- 你可以使用根布局来定义必需的 `<html>` 和 `<body>` 标签，并注入全局元数据（Metadata，后续章节将做详细讲解）。

由于刚才创建的新布局（`/app/dashboard/layout.tsx`）是仪表盘页面专用的，因此你无需将仪表盘的 UI 放入全局的根布局中。

### 6.2 嵌套路由（Nested Layout）：只在特定路由范围内共享 UI

Dashboard Layout 的文件位置是：

```text
app/dashboard/layout.tsx
```

它只针对 Dashboard 对应的路由层级提供共享 UI。这与 Root Layout 的作用范围不同：

| 对比 | Root Layout | Dashboard Layout |
|---|---|---|
| 文件位置 | `app/layout.tsx` | `app/dashboard/layout.tsx` |
| 作用范围 | 整个应用 | 对应的 Dashboard 路由层级 |
| 本章示例 | HTML、Body、全局 CSS、字体 | SideNav、Dashboard 主体容器 |
| 布局关系 | 顶层布局 | 嵌套在根布局之下 |

根布局已经提供了全局结构，因此不需要再把只属于 Dashboard 的侧边栏放进去。

---

### 6.3 为什么不把所有 UI 都放在 Root Layout 中？

如果把 SideNav 放在 Root Layout 中，它就会成为整个应用共享结构的一部分。

但本章的设计目标是让 SideNav 只出现在 Dashboard 页面中，而不是必然出现在所有应用页面中。

因此，布局的层级应该与 UI 的共享范围对应：

- 整个应用都需要的结构，放在 Root Layout。
- 一组特定页面需要共享的结构，放在对应的 Nested Layout。
- 单个路由专属的内容，放在对应的 Page。

各个布局分别承担自己的职责，并通过嵌套关系组成页面。**这是从本章示例中可以得到的布局设计原则**。

## 7. Partial Rendering：页面切换时为什么可以保留布局

### 7.1 本章讨论的问题

Dashboard 中有多个页面，它们共享同一个布局。

例如，在 Customers 和 Invoices 之间切换时，侧边栏不需要因为页面内容变化而从头组织一次。

原文指出，Next.js 的布局具有一个重要特性：

> 导航时，页面组件会更新，而布局不会重新渲染。这称为 Partial Rendering，并且可以在页面切换时保留布局中的客户端 React State。

这里的 Partial Rendering 是本章对页面导航行为的描述。

---

### 7.2 用页面切换来理解

假设当前访问：

```text
/dashboard/customers
```

页面结构为：

```text
Dashboard Layout
├── SideNav
└── Customers Page
```

然后导航到：

```text
/dashboard/invoices
```

从本章的概念模型来看：

```text
Dashboard Layout
├── SideNav
└── Invoices Page
```

变化发生在页面内容部分；共享布局则继续服务于相应的 Dashboard 页面。

可以将其理解为一个固定框架承载不同的页面主体。这个比喻用于理解 UI 结构，不代表框架在底层一定通过某种特定的 DOM 替换操作实现。

---

### 7.3 Partial Rendering 与状态保留的关系

为什么布局复用对状态有意义？

考虑一个放在共享布局中的客户端 UI 组件，它可能拥有需要在页面切换后继续使用的 React State。

如果导航导致共享布局整体被重新创建，其内部状态可能受到影响。原文强调的布局复用机制，则有助于在 Dashboard 子页面之间导航时保留布局中的客户端状态。

因此，可以把这一关系理解为：

```text
多个页面共享布局
        ↓
导航时复用共享布局
        ↓
避免因布局被重新创建而丢失其客户端状态
```

需要注意，这里不是说所有状态都天然得到保留，而是解释原文指出的共享布局与客户端 React State 的联系。

---

### 7.4 理解边界

**本章提供了 Partial Rendering 的基本概念，但没有详细介绍其内部实现**。因此，本章不需要回答诸如 Next.js 如何具体调度每次导航、底层如何缓存路由结果等实现级问题。**也不要把“布局不会重新渲染”简单扩大成“整个应用中的所有组件永远不会重新渲染”**。

当前阶段应该掌握的是：**共享布局可以在子页面导航中得到复用，这既减少了重复的界面组织，也有助于保留布局中的客户端状态。**

## 8. 把整章知识串起来：一次完整的页面组织过程

假设要为 Dashboard 添加一个 Reports 页面。

### 第一步：建立路由位置

创建：

```text
app/dashboard/reports/
```

这一目录建立了新的路径层级。

### 第二步：定义页面

创建：

```text
app/dashboard/reports/page.tsx
```

```tsx
export default function Page() {
  return <p>Reports Page</p>;
}
```

根据本章的文件系统路由规则，该页面对应 `/dashboard/reports`。

### 第三步：确认共享布局

因为 Reports 位于 `dashboard/` 之下，它属于 Dashboard 的路由层级。

在本章的结构中，不需要为了 Reports 再复制一份 SideNav。它可以使用现有的 Dashboard Layout。

### 第四步：推演组件结构

访问 `/dashboard/reports` 时，页面结构可以理解为：

```text
RootLayout
└── Dashboard Layout
    ├── SideNav
    └── Reports Page
```

这一过程综合了本章的几个概念：

1. 文件系统路由决定 URL。
2. `page.tsx` 定义页面内容。
3. Dashboard Layout 提供共享 UI。
4. Root Layout 提供应用级结构。
5. 页面与布局通过 `children` 关系进行组合。

这就是本章知识能够迁移到新页面的原因：**你不需要针对每个页面重新设计整套组件结构，而是按照既定的路由和布局关系进行扩展**。

---

## 9. 本章的核心心智模型

最后，用一条关系链把本章压缩起来：

**文件夹组织路由路径 → `page.tsx` 定义页面内容 → `layout.tsx` 组织共享 UI → `children` 连接布局与页面 → Root Layout 和 Nested Layout 形成层级 → Partial Rendering 解释共享布局在页面导航中的作用。**

真正理解本章，意味着你可以看到一段目录结构，就推导出它对应的 URL；看到一个布局组件，就解释它如何组织页面；面对一个新的 Dashboard 页面，也能判断应该新增什么文件，以及哪些 UI 可以直接复用。

这比单纯记住 `page.tsx` 和 `layout.tsx` 的用法更重要，因为它建立的是理解后续 Next.js 路由与导航功能所需要的基础模型。

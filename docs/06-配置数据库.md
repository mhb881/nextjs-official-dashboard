# 第 6 章：配置数据库 (Setting Up Your Database)

在继续开发仪表盘之前，你需要准备一些数据。在本章中，你将通过 Vercel 的市场集成（Marketplace Integrations）配置一个 PostgreSQL 数据库。如果你已经熟悉 PostgreSQL 并希望使用自己的数据库提供商，也可以跳过此章自行配置。

**本章内容概览：**

- 将项目推送到 GitHub。
- 设置 Vercel 账号并关联 GitHub 仓库，实现即时预览与自动化部署。
- 创建 Postgres 数据库并将其与项目进行绑定。
- 使用初始数据对数据库进行播种（Seed）。

---

### 创建 GitHub 仓库

首先，如果尚未操作，请将本地代码仓库推送到 GitHub。这能简化后续连接数据库与线上部署的流程。

> **实用建议：**
>
> - 你也可以使用 GitLab 或 Bitbucket 等其他 Git 代码托管平台。
> - 如果你是 GitHub 新手，推荐使用 GitHub Desktop 桌面客户端来简化开发操作。

访问 [vercel.com/signup](https://vercel.com/signup) 注册账号。选择免费的“Hobby”方案，并点击“Continue with GitHub”完成 GitHub 与 Vercel 账号的授权绑定。

### 创建 Postgres 数据库

接下来配置数据库：

点击 **Continue to Dashboard**，在项目控制台中进入 **Storage** 选项卡。

点击 **Create Database**。根据当前 Vercel 支持的集成服务，你可能会看到 Neon 或 Supabase 等数据库选项，选择偏好的提供商并点击 **Continue**。

![image-20261031191116581](./06-配置数据库.assets/image-20261031191116581.png)



按需选择服务器区域（Region）与存储方案。Vercel 项目的[默认区域](https://vercel.com/docs/functions/configuring-functions/region)通常是华盛顿特区（`iad1`），如果可用，建议选择该区域以最大限度降低数据[请求延迟](https://developer.mozilla.org/en-US/docs/Web/Performance/Understanding_latency)。

![image-20261031191131021](./06-配置数据库.assets/image-20261031191131021.png)

连接成功后，进入 **.env.local** 选项卡，点击 **Show secret** 并点击 **Copy Snippet** 复制代码片段（务必先显示密钥再复制）。

![image-20261031191144879](./06-配置数据库.assets/image-20261031191144879.png)

回到本地代码编辑器，将根目录下的 `.env.example` 文件重命名为 `.env`，并将从 Vercel 复制的环境变量粘贴进去。

> **安全注意**：检查根目录下的 `.gitignore` 文件，务必确认 `.env` 已列入忽略规则中，防止敏感的数据库连接凭据被意外推送到公开的 GitHub 仓库。

### 数据库播种（Seed your database）

数据库创建完成后，我们需要向其中写入基础初始数据。

项目中已内置了一个可通过浏览器访问的 API 路由，它会执行播种脚本（Seed script）来填充初始数据。该脚本使用原生 SQL 建表，并在建表完成后读取 `placeholder-data.ts` 中的模拟数据写入数据库。

1. 确保本地开发服务器已运行（`pnpm run dev`）。
2. 在浏览器中访问 `localhost:3000/seed`。
3. 执行成功后，浏览器中会返回信息：`"Database seeded successfully"`。
4. 播种完成后，可根据需要删除该路由文件以保证接口安全。

> 常见故障排查（Troubleshooting）
>
> - **环境变量缺失**：从 Vercel 复制前一定要点击“Show secret”，确保复制到 `.env` 的是真实连接串而非占位符。
> - **密码哈希依赖**：播种脚本默认使用 `bcrypt` 对测试用户密码进行哈希加密。如果 `bcrypt` 提示与当前 Node/系统环境不兼容，可将脚本中的依赖替换为纯 JS 实现的 `bcryptjs`。
> - **重置并重新播种**：如果在播种过程中报错需要重新执行，可以在数据库控制台的 Query 界面中运行 `DROP TABLE tablename` 删表后重试。*注意：该命令会直接清空表及其所有数据，切勿在生产环境中使用。*

### 执行查询（Executing queries）

让我们执行一次实际查询，验证数据库连接与数据写入是否正常。

项目中提供了另一个路由处理器（Route Handler）：`app/query/route.ts`。在该文件中，定义了包含如下 SQL 逻辑的 `listInvoices()` 函数：

```SQL
SELECT invoices.amount, customers.name
FROM invoices
JOIN customers ON invoices.customer_id = customers.id
WHERE invoices.amount = 666;
```

取消该文件中的代码注释，移除测试用的 `Response.json()` 限制，然后在浏览器中访问 `localhost:3000/query`。如果一切正常，界面将返回发票金额以及关联的客户姓名。

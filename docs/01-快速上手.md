# 1. 内容概览

本章是 Next.js App Router 官方实战课程的第 1 章：**《Getting Started》（快速上手）**。

作为全栈财务仪表盘（Financial Dashboard）构建的开篇，本章的核心任务是建立现代工程化开发的标准工作流与规范骨架：

- 采用高性能包管理器 `pnpm` 与官方脚手架 CLI（`create-next-app`）克隆起始模版；
- 解析 Next.js App Router 推荐的工程分层目录结构（路由与控制流 `/app`、核心逻辑与数据层 `/app/lib`、纯展示组件层 `/app/ui`、静态资产 `/public`）；
- 解析基于 TypeScript 的领域实体建模与类型契约（`definitions.ts` 中的字符串字面量联合类型及整型金额设计）；
- 理解从无持久化阶段的占位数据（Placeholder Data）到数据库播种（Database Seeding）的数据演进路径；
- 启动基于端口 3000 的本地开发服务器并验证初始环境。

# 2. 快速上手

## 创建新项目

我们推荐使用 `pnpm` 作为你的包管理器（Package Manager），因为它比 `npm` 或 `yarn` 速度更快且更加高效。如果你尚未安装 `pnpm`，可以通过运行以下命令进行全局安装：

## **终端**

```
npm install -g pnpm
```

要创建 Next.js 应用程序，请打开终端，`cd` 进入你希望存放项目的文件夹，并运行以下命令：

```
npx create-next-app@latest nextjs-dashboard --example "https://github.com/vercel/next-learn/tree/main/dashboard/starter-example" --use-pnpm
```

该命令调用了 `create-next-app`——一个为你搭建 Next.js 应用程序骨架的命令行界面（Command Line Interface，CLI）工具。在上述命令中，你还通过 `--example` 标志指定了本课程专用的初始模版。

## 探索项目结构

不同于要求你从零编写所有代码的教程，本课程的大部分基础代码已经预先编写完毕。这更贴近真实的开发场景——在实际工作中，你通常是在现有的代码库基础之上进行迭代。

我们的目标是帮助你集中精力学习 Next.js 的核心特性，而不必把时间耗费在编写所有的基础应用代码上。

安装完成后，在代码编辑器中打开该项目，并进入 `nextjs-dashboard` 目录：

```
cd nextjs-dashboard
```

让我们花一点时间来熟悉这个项目。

## 目录结构

你会注意到该项目具有以下目录结构：

![image-20260927120946871](./01-快速上手.assets/image-20260927120946871.png)

- `/app`：包含应用程序的所有路由、组件和逻辑，这是你绝大部分时间工作的主目录。
- `/app/lib`：包含应用程序中使用的功能函数，**例如可复用的通用工具函数以及数据获取函数**。
- `/app/ui`：包含应用程序的所有 UI 组件，例如卡片、数据表格和表单。为了节省时间，我们已经为这些组件预先编写了样式。
- `/public`：包含应用程序的所有静态资产，例如图片文件。
- **配置文件**：你还会在应用程序的根目录下看到诸如 `next.config.ts` 之类的配置文件。大部分配置文件是在使用 `create-next-app` 初始化新项目时由系统自动创建并完成预配置的。在本课程中，你不需要修改它们。

你可以随意探索这些文件夹，如果目前还不能完全理解所有代码的具体运作机制，也不必担心。

## 占位数据

在构建用户界面时，预先准备一些占位数据（Placeholder Data）会很有帮助。如果数据库或 API 尚不可用，你可以：

- 使用 JSON 格式或 JavaScript 对象形式的占位数据；
- 使用类似 mockAPI 的第三方 Mock 服务。

在本项目的 `app/lib/placeholder-data.ts` 文件中，我们提供了一些占位数据。该文件中的每个 JavaScript 对象都对应着数据库中的一张表。例如，发票表（`invoices`）的数据结构如下：

```ts
// /app/lib/placeholder-data.ts
const invoices = [
  {
    customer_id: customers[0].id,
    amount: 15795,
    status: 'pending',
    date: '2022-12-06',
  },
  {
    customer_id: customers[1].id,
    amount: 20348,
    status: 'pending',
    date: '2022-11-14',
  },
  // ...
];
```

在后续关于配置数据库的章节中，你将使用这些数据对数据库进行数据播种（Database Seeding，即使用初始数据填充数据库）。

## TypeScript

你可能还会注意到，绝大多数文件都以 `.ts` 或 `.tsx` 为后缀。这是因为该项目是采用 TypeScript 编写的。我们希望打造一门能够反映现代 Web 技术生态的课程。

如果你不熟悉 TypeScript 也没关系——在需要的时候，我们会直接提供对应的 TypeScript 代码片段。

现在，看一下 `/app/lib/definitions.ts` 文件。在这里，我们手动定义了数据库查询将返回的数据类型。例如，`invoices` 表包含以下类型定义：

```ts
// /app/lib/definitions.ts
export type Invoice = {
  id: string;
  customer_id: string;
  amount: number;
  date: string;
  // 在 TypeScript 中，这被称为字符串字面量联合类型（string union type）。
  // 它表示 "status" 属性的值只能是两个字符串之一：'pending' 或 'paid'。
  status: 'pending' | 'paid';
};
```

通过使用 TypeScript，你可以确保自己不会意外地将错误格式的数据传递给组件或数据库，例如防止把字符串错误地赋给发票金额（`amount`）。

如果你是一名 TypeScript 开发者：

- 虽然我们目前是手动声明数据类型，但为了获得更完善的端到端类型安全（Type-safety），我们推荐使用 Prisma 或 Drizzle，它们能够根据数据库 Schema 自动生成对应的类型。
- Next.js 能够自动检测项目是否启用了 TypeScript，并自动安装必要的依赖包和生成配置文件。Next.js 还为代码编辑器提供了专用的 TypeScript 插件，以支持自动补全与类型检查。

## 启动开发服务器

运行 `pnpm i` 安装项目的依赖包：

```
pnpm i
```

随后运行 `pnpm dev` 启动本地开发服务器：

```
pnpm dev
```

`pnpm dev` 将在 3000 端口启动你的 Next.js 开发服务器。让我们检查一下它是否正常运行。

# Next.js Dashboard 控制台全站组件规范重构与设计体系

> 本文档详细记录了以 `src/app/page.tsx` 与 `src/ui/dashboard/sidenav.tsx` 为设计标杆，对控制台核心布局、统计卡片、图表、列表、表格、分页以及操作按钮进行的全站组件规范重构过程、设计哲学及工程实现。

---

## 一、 背景与原版问题诊断

在首页（`src/app/page.tsx`）与侧边导航栏（`src/ui/dashboard/sidenav.tsx`）完成现代化重构后，项目建立了一套基于**双层圆角分级、微动效反馈、递进内边距和呼吸感空态**的设计基准。

然而，对比审查控制台内部的其他核心组件（`layout.tsx`、`cards.tsx`、`revenue-chart.tsx`、`latest-invoices.tsx`、`table.tsx`、`buttons.tsx`、`status.tsx` 等）时，存在明显的**设计语言脱节与视觉断层**：

### 1. 容器边界与版心失控
* **原版现象**：`src/app/dashboard/layout.tsx` 中直接写死 `p-6 md:p-10`，在移动端小屏上占用了过宽的边距，挤压了数据图表的可用空间；而在 2K/4K 等大屏显示器上没有任何最大宽度（`max-w`）限制，导致卡片和表格被横向无休止拉扯，视觉信息发散。

### 2. 圆角与包裹层级混淆
* **原版现象**：组件内部 `rounded-md`、`rounded-lg`、`rounded-xl` 随意穿插。例如原版 `cards.tsx` 外层是 `rounded-xl`，内层包裹数字的容器又是一个 `rounded-xl`，缺少父子包裹时的视觉收敛规则。

### 3. 缺乏微动效与触控反馈（静态死板）
* **原版现象**：按钮、卡片、列表行多为纯静态或仅有粗糙的背景变色。缺少移动端触摸所需的 `active:scale-95` 按压缩放反馈，缺少桌面端悬浮的 `hover:shadow-md` 浮动感，图标亦无悬浮联动。

### 4. 空态体验生硬简陋
* **原版现象**：`revenue-chart.tsx` 在无数据时仅渲染一行冷冰冰的 `<p className="mt-4 text-gray-400">No data available.</p>`，破坏了整体卡片化的版面结构，未延续 `sidenav.tsx` 中已经成熟的虚线呼吸占位风格。

### 5. 状态色与语义色彩过载
* **原版现象**：`status.tsx` 中已支付状态直接使用高饱和的纯绿 `bg-green-500 text-white`，与整体偏向温和、沉稳的灰蓝中性底色极不协调。

## 三、 详细设计思路与工程落地

### 1. 圆角与包裹分级（Radius & Containment Hierarchy）

在现代界面设计中，圆角不是单点的视觉装饰，而必须遵循物理几何包裹的**嵌套收敛法则**：
* **一级外壳（宏观容器）**：统一使用 `rounded-xl` (12px)。包括页面外层大卡片、Hero Banner、侧边栏外壳、图表底座、虚线占位槽、表格外框。
* **二级控件（交互组件）**：统一使用 `rounded-lg` (8px)。包括输入框、按钮（创建/编辑/删除）、导航链接（NavLinks）、发票行悬停高亮底色。
* **微型修饰（标签与头像）**：使用 `rounded-full` 或 `rounded-md` (4~6px)。用于状态胶囊、用户头像以及柱状图顶角。

通过这套清晰的规则，全站消除了原本杂乱无章的圆角搭配，视觉整体感大幅提升。

### 2. 触控感知与微交互体系（Tactile Micro-Interactions）

为了让整个管理后台摆脱传统“政企系统”的迟钝感，我们在全站组件中深度融入了与 `page.tsx` 和 `sidenav.tsx` 相同的交互动效：
* **平滑基础过渡**：全局显式配置 `transition-all duration-200`，杜绝生硬的瞬变。
* **物理按压反馈（Active Scale）**：
  - 核心操作按钮采用 `active:scale-95`；
  - 较大面积的卡片采用 `active:scale-[0.99]`；
  让移动端触摸或桌面鼠标点击时拥有极佳的弹性物理手感。
* **悬浮状态提升（Elevation）**：
  - 常态使用低调的 `shadow-xs` 或纯边框 `border-gray-200/80`；
  - 悬浮时切换为 `hover:shadow-md hover:border-blue-200`，产生自然的上浮层级。
* **语义化色彩预警**：
  - 危险动作（如删除发票、登出）悬浮时不使用突兀的大红，而是采用温和的 `hover:bg-red-50 hover:text-red-600 hover:border-red-200`，既提示风险又不产生视觉疲劳。

### 3. 呼吸感与优雅空态（Graceful Empty States）

借鉴 `sidenav.tsx` 中通过虚线边框营造弹性空白区的成功经验：
```tsx
{/* 优雅的空态呼吸卡片 */}
<div className="flex h-[380px] flex-col items-center justify-center rounded-xl border-2 border-dashed border-gray-200 bg-gray-50/70 p-6 text-center">
  <CalendarIcon className="mb-2 h-8 w-8 text-gray-400" />
  <p className="text-sm font-medium text-gray-600">No revenue data available.</p>
  <p className="mt-1 text-xs text-gray-400">
    Revenue trends will appear here once invoices are paid.
  </p>
</div>
```
当数据库处于初始无数据状态时，页面不再是干瘪的单行错误提示，而是依然保持着稳健的卡片骨架与图文指引，极大提升了产品的完整度。

### 4. 状态胶囊与色彩克制（Color Temperance）

原版发票状态徽章采用了高对比度的纯实心背景（`bg-green-500 text-white`），在白色表格中显得过于突兀且抢夺视线。本次重构采用业内公认的最佳实践（Soft Tint + 1px Ring）：
```tsx
<span
  className={clsx(
    "inline-flex items-center gap-1.5 rounded-full px-2.5 py-1 text-xs font-medium transition-colors",
    {
      "bg-amber-50 text-amber-700 ring-1 ring-amber-600/20": status === "pending",
      "bg-emerald-50 text-emerald-700 ring-1 ring-emerald-600/20": status === "paid",
    },
  )}
>
  ...
</span>
```
这种设计不仅视觉轻盈柔和，而且符合 WCAG 2.1 AA 级无障碍对比度标准。

### 5. 表格骨架屏像素级对齐（解决 CLS 布局漂移）

在发票列表页（`invoices/page.tsx`）中，数据表格被包裹在 `<Suspense fallback={<InvoicesTableSkeleton />}>` 中，下方紧跟着 `<Pagination>`。若骨架屏与真实渲染出的表格高度存在偏差，数据到达时下方的分页条便会剧烈“上下跳跃”，产生累积布局偏移（CLS）：

* **表头高度对齐**：真实表头使用 `py-4`（高度 48px），修正 Skeleton 中残留的 `py-5`（高度 56px），消除表头 8px 的向上跳动；
* **数据行高对齐**：统一单元格 `py-3.5`，并将头像尺寸严格锁定为 `h-7 w-7`（28px，1:1 吻合 Next.js Image 组件），操作按钮统一定制为 `h-[34px] w-[34px] rounded-lg` 且间距锁定为 `gap-2`；
* **移动端卡片精准拟真**：修复了原版移动端 Skeleton 中上内边距写成 `pb-8`（32px）的巨大缺陷（真实为 `pb-3`，相差 20px），并统一卡片间距为 `mb-3`、状态徽章为 `rounded-full`，彻底消除了移动端 120px+ 的垂直跳跃；
* **注入 Shimmer 动态光泽**：外层容器追加 `${shimmer} relative overflow-hidden`，确保骨架屏在流式加载期间呈现自然流畅的光波扫掠效果。
